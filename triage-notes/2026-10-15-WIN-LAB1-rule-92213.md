## Scope

This note covers only the rule 92213 alert generated by the creation of the PowerShell policy test file.

## Summary

The creation of a PowerShell script in `AppData\Local\Temp` was detected. The investigation showed that the file was generated automatically by PowerShell when the user started it interactively. The activity is legitimate.

## Evidence

### Process tree

```
explorer.exe  (WIN-LAB1\Win-Lab0)
└── powershell.exe  (PID 9748, IntegrityLevel: Medium)
    └── creates __PSScriptPolicyTest_gyoffyrx.xy5.ps1  (in the Temp folder)
```

### Key fields

| Field | Value |
|---|---|
| `ParentImage` | `explorer.exe` |
| `Image` | `powershell.exe` |
| `IntegrityLevel` | `Medium` |
| File created | `__PSScriptPolicyTest_*.ps1` |

### Checks

- The parent process is `explorer.exe`, running in the user's interactive session (`TerminalSessionId: 1`).
- The integrity level (`Medium`) shows it did not run with administrator privileges.
- The created file follows the standard naming pattern PowerShell uses for execution policy tests (`__PSScriptPolicyTest_*.ps1`).
- The correlation was confirmed in the local Sysmon log using the `ProcessGuid`.

## Analysis

The alert fired because rule 92213 detects any script created in `AppData\Local\Temp`. However, when PowerShell starts interactively, it automatically creates a temporary file to test the execution policy. The process tree confirms that the user started it in a benign way, not a malicious process.

## Verdict

**False positive:** temporary file generated automatically by standard PowerShell behavior at startup.

## Actions and recommendations

1. Close the rule 92213 alert for this event.
2. **Proposed tuning (not applied):** modify rule 92213 to exclude files created in `AppData\Local\Temp` whose name matches the pattern `__PSScriptPolicyTest_*.ps1`.
3. **Tuning risk:** a malicious script could be named on purpose with the `__PSScriptPolicyTest_*.ps1` pattern to evade detection in the Temp folder.
4. **Mitigation:** make the exclusion also require that the creating process (`Image`) is exactly `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe` or `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`.
5. **Blind spot lesson:** the process creation event (Event ID 1) was not recorded in Wazuh, so I had to investigate directly in the local Sysmon log on the endpoint to confirm the execution chain.
