## Scope

27 alerts of rule 92213 on WIN-LAB1, all within one minute after the VM was powered on.

## Summary

The 27 alerts came from only **2 processes**, both started by Windows scheduled maintenance:

- **26 alerts:** `cleanmgr.exe` (task SilentCleanup) copied DISM components (`DismHost.exe` and 25 DLLs) to a temporary folder and ran `DismHost.exe` from there.
- **1 alert:** `sdiagnhost.exe` (Windows troubleshooting host) created a `__PSScriptPolicyTest_*.ps1` file, the PowerShell execution policy test.

Both are **false positives**. The case matters because the same file pattern is a known **UAC bypass** (a malicious DLL planted in the DismHost folder runs elevated without a UAC prompt), and `sdiagnhost.exe` was abused by **Follina** (CVE-2022-30190).

## Analysis

When a VM is powered on after being off, Windows runs the scheduled tasks it missed. SilentCleanup and a scripted diagnostic were two of them, and both write files to `AppData\Local\Temp`, which is what rule 92213 watches.

**cleanmgr.exe:** the parent, command line and image path match the legitimate SilentCleanup task. In a UAC bypass, a **different process** would write a DLL into the DismHost folder before `DismHost.exe` loads it. Here every file was written by cleanmgr.exe, and `DismHost.exe` is identical to the Windows original.

**sdiagnhost.exe:** the direct parent does not separate legitimate from malicious use, because COM always starts it from `DcomLaunch`. The deciding evidence is that no suspicious process requested the diagnostic and sdiagnhost.exe launched no child processes.

**Residual risk:** no hashes or image-load events were available for the 25 DLLs, so their integrity was not verified directly. Mitigated by check 4.

## Verdict

**False positive.** Windows scheduled maintenance at VM startup (SilentCleanup and Scripted Diagnostics).

## Actions

### Proposed tuning

A Wazuh child rule of 92213 that **lowers the level from 15 to 3** (still stored and searchable, no email or high priority) only when:

- `win.eventdata.image` is exactly `C:\Windows\System32\cleanmgr.exe`, and
- `win.eventdata.targetFilename` is in `AppData\Local\Temp\<GUID>\` and is `DismHost.exe` or a DISM DLL.

**Limitation:** Sysmon Event ID 11 has no parent process or command line, so the rule cannot check `/autoclean`.

**Risk:** a malicious DLL written **by cleanmgr.exe itself** would be lowered to level 3.

**Mitigation:** in the known bypass, the DLL is written by another process, which still triggers level 15. The events stay in the index for hunting.

Not applied yet. It will be written and tested with `wazuh-logtest` in the detection-as-code project.

The sdiagnhost.exe alert is left unchanged: one alert per startup, and the parent cannot separate it from Follina.
